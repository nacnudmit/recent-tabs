# Chrome Web Store Submission Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare the Recent Tabs extension for Chrome Web Store submission as an unlisted item: an icon set, a privacy policy page, manifest updates, a packaging script producing a clean submission zip, draft store-listing copy, and a manual submission checklist.

**Architecture:** A one-off Python/Pillow script generates the icon PNGs at three sizes from a single drawing. `manifest.json` gains an `icons` block, `action.default_icon`, and a version bump. A standalone privacy policy HTML file and two markdown docs (listing copy, submission checklist) live outside the packaged extension. A shell script builds the submission zip from exactly the files Chrome needs.

**Tech Stack:** Python 3 with Pillow (already available in this environment) for icon generation, bash + `zip` for packaging, plain HTML/Markdown for the policy and docs. No changes to the extension's JS runtime behavior.

## Global Constraints

- Visibility: Unlisted (not searchable in the Chrome Web Store).
- No new runtime permissions — the extension's `permissions` array stays `["tabs", "storage"]`.
- The packaged zip must contain ONLY: `manifest.json`, `background.js`, `popup.html`, `popup.js`, `options.html`, `options.js`, `icons/`. Nothing else (no docs, no dev tooling, no privacy policy file).
- Icon sizes: exactly 16×16, 48×48, 128×128 PNG, transparent background.
- Version bumps from `1.0.0` to `1.1.0`.
- No automated test framework for the extension's runtime behavior (unchanged from the rest of the project) — but icon dimensions and zip contents ARE mechanically verifiable without Chrome, and this plan's tasks do so directly.

### Task 1: Generate icon set and wire into manifest

**Files:**
- Create: `tools/generate_icons.py`
- Create (generated by running the script): `icons/icon16.png`, `icons/icon48.png`, `icons/icon128.png`
- Modify: `manifest.json`

**Interfaces:**
- Produces: three PNG files at `icons/icon16.png`, `icons/icon48.png`, `icons/icon128.png`, referenced by `manifest.json`'s new `icons` and `action.default_icon` blocks. No other task depends on the icon files' pixel content, only their existence and correct dimensions.

- [ ] **Step 1: Write the icon generator script**

Create `tools/generate_icons.py`:

```python
import math
import os

from PIL import Image, ImageDraw

SIZE = 128
TAB_COLOR = (74, 144, 217, 255)
BACK_TAB_COLOR = (58, 115, 173, 255)
ACCENT_COLOR = (255, 255, 255, 255)

img = Image.new("RGBA", (SIZE, SIZE), (0, 0, 0, 0))
draw = ImageDraw.Draw(img)

# Back tab (offset behind, darker shade)
draw.rounded_rectangle([28, 20, 108, 76], radius=14, fill=BACK_TAB_COLOR)
# Front tab
draw.rounded_rectangle([16, 40, 96, 96], radius=14, fill=TAB_COLOR)

# Circular "cycle" arrow accent
cx, cy, r = 78, 78, 22
bbox = [cx - r, cy - r, cx + r, cy + r]
draw.arc(bbox, start=30, end=300, fill=ACCENT_COLOR, width=6)

angle = math.radians(30)
ax = cx + r * math.cos(angle)
ay = cy + r * math.sin(angle)
arrow_size = 10
draw.polygon(
    [
        (ax, ay - arrow_size),
        (ax + arrow_size, ay),
        (ax - 2, ay + 4),
    ],
    fill=ACCENT_COLOR,
)

script_dir = os.path.dirname(os.path.abspath(__file__))
icons_dir = os.path.join(script_dir, "..", "icons")
os.makedirs(icons_dir, exist_ok=True)

img.save(os.path.join(icons_dir, "icon128.png"))

for size in (48, 16):
    resized = img.resize((size, size), Image.LANCZOS)
    resized.save(os.path.join(icons_dir, f"icon{size}.png"))

print("Generated icons/icon16.png, icons/icon48.png, icons/icon128.png")
```

**Files:**
- Create: `privacy-policy.html`

**Interfaces:**
- Produces: a standalone HTML file with no dependency on any other file in the repo. Not referenced by the extension itself (Chrome doesn't load it) — it's for the user to host externally and link from the Web Store dashboard.

- [ ] **Step 1: Write `privacy-policy.html`**

<html lang="en">
<head>
  <meta charset="utf-8">

<body>
  <h1>Recent Tabs — Privacy Policy</h1>
  <p>Recent Tabs does not collect, transmit, sell, or share any user data with any third party or server. There is no backend, no analytics, and the extension makes no network requests of any kind.</p>

  <h2>What the extension reads</h2>
  <p>Recent Tabs uses Chrome's <code>tabs</code> permission to read tab titles, favicon URLs, and tab/window IDs. This information is used solely to build and display the recently-used-tabs list within the extension's own popup, and to switch between tabs. This data never leaves your browser.</p>

  <h2>What the extension stores</h2>
  <p>The extension stores two things, both using Chrome's built-in <code>storage</code> APIs, both entirely local to your own browser/account:</p>
  <ul>
    <li><strong>Per-window recent-tabs lists</strong> — stored in <code>chrome.storage.session</code>, cleared automatically when Chrome fully restarts.</li>
    <li><strong>Your chosen "tabs remembered" setting</strong> — stored in <code>chrome.storage.sync</code>, which Chrome syncs across your own signed-in devices using your Google account's built-in sync. This data is not accessible to the developer of this extension or to anyone else.</li>
  </ul>

  <h2>Accounts and personal information</h2>
  <p>Recent Tabs does not require or collect any account, sign-in, or personal information.</p>

  <h2>Contact</h2>
  <p>Questions about this policy can be directed to the extension's listed support contact on the Chrome Web Store.</p>
</body>
</html>

### Task 3: Packaging script

**Files:**
- Create: `package.sh`

**Interfaces:**
- Produces: `recent-tabs.zip` when run (the zip itself is a build artifact, not committed to git). No other task depends on this script's internals, only that running it produces a correctly-scoped zip.

- [ ] **Step 1: Write `package.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

cd "$(dirname "$0")"

rm -f recent-tabs.zip

zip -r recent-tabs.zip \
  manifest.json \
  background.js \
  popup.html \
  popup.js \
  options.html \
  options.js \
  icons

echo "Built recent-tabs.zip"
```

- [ ] **Step 2: Make it executable**

Run: `chmod +x package.sh`

- [ ] **Step 1: Write `docs/store-listing.md`**

```markdown
# Chrome Web Store Listing Copy

Draft copy for the Chrome Web Store Developer Dashboard. Paste these into the corresponding fields when creating the listing.

## Summary (max 132 characters)

Cycle back through your last few tabs per window, with a visual overlay — configurable history length.

## Description

Recent Tabs remembers the tabs you've used most recently in each Chrome window and lets you jump straight back to them.

- Press a keyboard shortcut to cycle backward through your recently used tabs, with a small popup overlay showing your current position and letting you click any entry directly.
- Open the toolbar popup any time to see and jump to your recent tabs for the current window.
- Choose how many tabs to remember (5, 10, 15, or 20) from the extension's settings page.

Everything stays local to your browser — no accounts, no tracking, no data ever leaves your device except via Chrome's own built-in sync for your chosen settings.

## Single purpose

Recent Tabs' single purpose is recency-based tab navigation: helping the user quickly return to recently used tabs within the same browser window.

## Permission justifications

- **tabs**: Required to read tab titles, favicon URLs, and IDs to build the recency list, and to activate a tab when the user selects one. No tab content or browsing history beyond what's needed for this list is accessed.
- **storage**: Required to persist the per-window recency list (`chrome.storage.session`) and the user's chosen history-length setting (`chrome.storage.sync`).
```

# Chrome Web Store Submission Checklist

Manual steps to perform in the Chrome Web Store Developer Dashboard (https://chrome.google.com/webstore/devconsole). None of this can be done on your behalf — it requires your own Google account and payment method.

1. If you haven't already, register as a Chrome Web Store developer (one-time $5 USD fee).
2. Host `privacy-policy.html` somewhere with a public URL (GitHub Pages, a Gist's raw view, Google Sites, etc.) and note the URL.
3. Build the submission package: run `./package.sh` from the repo root to produce `recent-tabs.zip`.
4. In the dashboard, click "New Item" and upload `recent-tabs.zip`.
5. Fill in the "Store Listing" tab using the copy from `docs/store-listing.md`:
   - Summary
   - Description
   - Category (suggest: Productivity)
   - Language
6. Under "Privacy practices":
   - Paste the privacy policy URL from step 2.
   - Fill in the single-purpose description and permission justifications from `docs/store-listing.md`.
   - Declare data usage honestly: no data collected, no data sold, no data used for purposes unrelated to the extension's core functionality.
7. Under "Distribution" / "Visibility", set the listing to **Unlisted**.
8. Upload the 128×128 icon (`icons/icon128.png`) as the store listing icon if the dashboard requests one separately from the manifest icon.
9. Review the summary page, then submit for review.
10. Chrome Web Store review can take anywhere from a few hours to several days. You'll receive an email when it's approved (or if changes are requested).
